# 主报告模板

> 三个已完成作品的骨架已归纳成下面这套。**加粗**项是每份报告都必须有的。
> 范文：`1846深度分析（672局）.md`（最完整）、`1830深度分析（532局）.md`、`1862深度分析（419局）.md`。

---

## 文首块（必需）

```markdown
# <作品> 深度分析（N 局）· vX.Y

> **分析人**：**Pig9013**　|　**使用模型**：**Deepseek-flash**　|　**整理日期**：**YYYY-MM-DD**
> **致谢**：全部对局数据来自 **[18xx.games](https://18xx.games/)** 及在该网站上游玩的玩家们——是他们无偿公开的游玩记录，造就了这些分析。
> **版本**：v1 → v1.1 …（逐版写清改了什么）
>
> **数据基础**：`复盘分析/<作品>/` N 个源文件 → 切出 M 局 → 去重后 **K 局唯一**
> **主统计样本**：**K' 局 / X 玩家场次 / Y 名玩家**（排除 N 局变体，原因）
> **局型构成**：2人 a｜3人 b｜4人 c｜5人 d…
> **对账**：**X/X 玩家场次 = 100.0% 精确吻合**
> **规则依据**：<出版方> <年份>版英文规则书，逐条核对
> **匿名化**：TOP 组保留真名，MID/BOT 组记作**玩家X**（分层边界与编号规则见 `玩家匿名化.md`）
>
> **本文性质**：这是**旧 <M> 局报告在新数据库上的完整重跑**。（若适用）
```

**文末**再加两行：

```markdown
*致谢：全部对局数据来自 [18xx.games](https://18xx.games/) 与在该站无偿公开对局的玩家们。*

*分析人：Pig9013　|　使用模型：Deepseek-flash　|　整理日期：YYYY-MM-DD*
```

## 目录（必需）

三列表格 `| 篇 | 节 | 内容 |`，篇用两个字概括（数据/玩家/局型/顺位/搭配/招股价/车站/火车/倒车/股份/画像/打法/速查/方法…），**内容列要写出该节的核心结论关键词**，不是章节名复述。

---

## 〇、数据与对账

| 小节 | 内容 |
|:--|:--|
| 0.1 属性截面 | 本作的公司/玩家有哪些**正交属性**？分别在什么时候确定、是否随机？（1862：2 × 3 × 20） |
| 0.2 对账 | 写清记账恒等式，报出**逐人吻合率**、残差中位/最大、残差来源 |
| 0.3 **日志句式陷阱** | 表格列出本作特有的解析陷阱 + 每一条造成的后果 |
| 0.4 局型构成 | 人数分布、变体局标记、样本规模的变化（旧版 → 新版） |
| 0.5 基线数字 | **全文对照用的基准**（全体均名次、胜率、终局资产中位数…） |

## 一、玩家层

- **1.1 口径：为什么这么定** —— 每个指标都要给出**"为什么不用那个更直觉的做法"**（例：为什么不能用场均名次）
- **1.2 定义三条基础口径** —— 归一化名次 / 前二率 / 分层依据
- **1.3 实力榜** —— 玩家 | 局数 | RR 分 | 90% 区间 | 名次分 | 前二率 | 夺冠率 | 局型
- **1.4 并列口径** —— 第二套实力分互为校验，给出相关系数 r
- **1.5 分层** —— TOP / MID / BOT 的切分线与人数
- **1.6 熟人局 vs 路人局** —— 判据 + 两者差异

**样本警告必须紧跟榜单**：哪些人 n 太少、区间多宽、不能与谁等同。

## 二、机制事实（先讲清，再谈策略）

用**规则原文 + 条款号**把本作的核心机制写清楚：阶段与列车、股市机制、与已分析作品的关键差异。**这一节不出现策略建议。**

## 三～N、主题章（按作品取舍）

每章统一结构：**机制 → 数据 → 案例 → 可操作结论**。常用主题：

| 主题 | 必答问题 |
|:--|:--|
| **开局/拍卖** | 成交价分布、"第几家"的价值判断难度、拿下几家的单调关系；随机属性（许可）如何绑定 |
| **par / 招股价** | 分布与甜点区、各组定价习惯、剔除特殊公司后的口径、定价动机 |
| **公司画像** | 逐家：出场率、发起时点、首购组合、路线、回报率、变异系数；"公司强弱 ≠ 发起者结局" |
| **车站** | 各家实际放哪、特权的使用率、首占 vs 落站谁更有解释力 |
| **列车与爆车** | 首车**组合**（不是车型频次）、爆车日历、爆车当口资金、谁最易被爆到无车、强制购车与总裁垫钱 |
| **公司间交易** | 谁卖给谁（自己卖给自己占比）、什么车、什么时点、什么价 |
| **股份行为** | 各组资金投向 %、买卖时机（按股票轮）、抛什么换什么、轮末砸价归因、持股时序 |
| **现金** | 分红 vs 留存（按玩家组 × 阶段）、超发/再融资、补贴 |
| **合并收购** | 频率、**目的归因**（补证/拿站/拿车）、**成本由谁承担**（逐股东口径）、时机 |
| **危机点** | 破产的规则口径（不是钱=0）、实测率、危机日历、谁最容易受害 |
| **地图与走廊** | 坐标系标定 → 路线使用率 → 主力走廊 → 枢纽度；或从日志反推 |
| **行为 × 残差总表** | 行为 | 出现频率 | 平均残差 | 样本 | 解读 |

## N+1、TOP 打法 vs 最低胜率打法

净效应最好/最差的打法各列若干条，**每条附样本量与案例**；反直觉的单独开小节讲。

## N+2、可执行结论速查

编号清单（15–25 条），每条一句话 + 数字。**这是读者上桌前唯一会看的部分。**

## N+3、方法与局限

- 数据与工具（**表格：环节 → 工具**）
- 交叉验证（至少两项）
- **局限 5–7 条**，每条都要具体（相关≠因果、残余循环、选择效应、小样本格子、局型不齐、手动结束局）

## 附录

- 与其他作品的框架对接（**逐条写"采用/不适用/方向相反"**）
- 本轮工具清单（脚本 → 作用 → 输出文件）

## 译成英文（**中译英的反向交付**）

**已完成实例**：
- `复盘分析/1846/1846 Deep Analysis (672 Games).md`（2303 行，2026-09-17）——术语表 `1846_EN_GLOSSARY.md`
- `复盘分析/1880China/1880China Deep Analysis (341 Games).md`（1410 行，2026-09-24，译自 v1.3）——术语表 `1880China_EN_GLOSSARY.md`；**12 分片并行 + 装配器 + 校验器全绿**，是最完整的样板

1. **先立译名标准**：`复盘分析/<作品>/<作品>_EN_GLOSSARY.md`，四类——规则术语（**用英文原规的原生词，不要回译**：`车站标记`→station marker、`招股价`→par price、`报废`→rust）、作品专有（查 `18XX_中英术语对照表.md` 的对应小节）、报告自定义分析词（前二制→top-two rank rating、熟人局→familiar table、倒车→inter-company train transfer…）、风格规约。
   > **先回英文原规 grep 一遍再定表**：1880 的口径是 `Director`（不是 President）、投资者是 British/French/German/Japanese/Portuguese/Russian、公司类别是 Major/Private Company——都是原规里的**原生词**，不能靠记忆或从其他作品推。
2. **硬规则**：直译不删减；**数字逐个照抄**；markdown 结构（标题层级、表格形状、代码块、块引用）原样保留；公司代码**一律不译**。
   > **货币按作品的规则书定，不要跨作品套用**：1846 报告里的 `¥` 是笔误、规则书用 `$`，故 **¥→$**；**1880 的规则书本身就印 `¥`**，故 **保留 ¥ 不转**。译前先 grep 原规的货币符号。
3. **玩家名的处理**（2026-09-24 起）：中文稿里的 **`玩家X` 一律译作 `PlayerX`，且 X 必须与中文稿完全一致**（同一编号）；**TOP 组的真名照抄不译**。译完跑
   `python _tools/anonymize_18xx.py --check` 校验英文稿无 MID/BOT 真名残留。
   > 若英文稿先于匿名化存在（如 1846 英文版 2026-09-17 版），**中英文要一起改**，编号必须对齐。
   > ⚠ **自译那一段最容易漏**：手工译封面/§0 时，日志示例与陷阱表里的 `玩家7`、`玩家19` 很容易被当成"引用"照抄过去。**译完必须用机器扫 `玩家\d+` 残留**（校验项 [5]）。
4. **三条排版转换**（中文源特有的坑）：
   - `——`（中文双破折号）→ `—`；
   - `「」` → `"…"`；全角冒号 `：` → `: `；全角括号/逗号/顿号同理；
   - **`｜`（全角竖线）：在表格行内必须转义为 `\|`，在正文行里则要转成普通 `|`**。⛔ 一刀切全转义会毁掉正文（1880 踩过）。装配器要按行判断。
5. **机器校验**（`_tools/verify_1880_translation.py` 最完善，可 fork）：① 标题层级序列；② **每张表格的行数**；③ **数字多重集**（**"源有译无"一个都不允许**——那就是漏数字；"译有源无"需逐条登记预期项，典型是中文数词译成阿拉伯数字）；④ 中文残留（**豁免两处**：§0.5 误译核查表引用的是被批评的中译原文；译本身世说明行）；⑤ **`玩家X` 残留**；⑥ **MID/BOT 真名残留**（复用匿名化映射）。
6. **产线**：① 通读全文 + grep 原规 → 立术语表；② **自译封面到 §1 定风格**；③ 其余按章节切片**并行**翻译（1880 = 11 片，每片给源行范围 + 术语表 + 风格样板，要求"直译完整、数字照抄、结构相同"，各自 Write 到 `_work/en<作品>/partN.md`）；④ `_tools/assemble_1880_translation.py` 装配 + 符号归一；⑤ 校验 → 修到六项全绿。
   > **切片要在源文冻结后再切**：1880 出现过"翻译启动后我才补改了中文源的版本沿革与 §8.1 人数"，导致 part1 与源文漂移、数字多重集报差异。**先定稿源文，再开译**；万一改了源文，用 `_tools/_check_1880_parts.py` 按切片重校。
