# 玩家匿名化（**每份 18xx 分析交付前必做**）

> 用户 2026-09-24 明确要求，并已回溯应用到全部既有交付物（14 个 .md + 2 个 .pptx）。
> **今后每一份 18xx 分析、复盘、速查、PPT，交付前都要走一遍这个流程。**

## 0. 一句话口径

**TOP 组保留真名；MID / BOT 组一律替换成「玩家X」（英文版 `PlayerX`）。**

## 1. 理由（写给别人看时用）

18xx.games 是公开站，但站上多数玩家是普通人。报告会具体点评"谁在哪一局做了什么、犯了什么错"，
点名对当事人没有好处。**保留 TOP 组是因为那些结论本来就是围绕强手展开的、当事人也多为公开玩家；
MID/BOT 的具体失误不值得被永久索引到真人。** 这与 §3.1 的致谢并不矛盾——
致谢是给全体玩家的，点名点评是另一回事。

## 2. 分层边界（**各作品独立，不得跨作品统一**）

| 作品 | TOP（保留真名） | MID | BOT |
|:--|:--|:--|:--|
| **1846** | **报告印出的 9 人名单**（=RR 分前 9 名） | 1600 ≤ RR < 1900 且 ≥8 局 | RR < 1600 且 ≥8 局 |
| **1880** | BT ≥ 2.0 且 ≥8 局（8 人） | 0.7 ≤ BT < 2.0 且 ≥8 局（13 人） | BT < 0.7 且 ≥8 局（15 人） |
| **1830** | BT ≥ 1700 且 ≥10 局（6 人） | **无 MID 档** | BT ≤ 1420 且 ≥10 局（6 人） |
| **1862** | BT ≥ 1700（报告口径「强手」） | 1500 ≤ BT < 1700 | BT < 1500 |

**⚠ 1846 的坑**：报告 §1.5 原先写「TOP = RR ≥ 1900 且 ≥8 局」，但**实际印出的 9 人是 RR 分前 9 名**，
两者差 3 人（cougar 1941/8 局、Kubigaruma 1923/9 局、mjmill13 1906/23 局 按规则属 TOP、按名单属 MID）。
**用户 2026-09-24 指定：一律以印出名单为准**，那 3 人按 MID 段匿名化。报告里已加口径说明块，勿删。

**1862 的特殊性**：报告本身没有 TOP/MID/BOT 概念，只有「强手 BT≥1700 / 弱手 BT<1500」。
匿名化沿用这条线，**不新增口径**。

## 3. 编号规则

- **每份作品内独立编号**（同一人在 1846 是玩家7、在 1862 可能是玩家12 —— 这是**特性不是 bug**，
  跨报告不可关联本身就是匿名化想要的）。
- **只给"正文里实际出现"的 MID/BOT 玩家编号**，按**实力分从高到低**、**MID 段在前 BOT 段在后**连续编号。
  （不出现的玩家不编号——否则会出现「玩家312」这种离谱编号。）
- **未达分层门槛（样本太少）但出现在正文者**，追加在末尾，档位标 `EXTRA`。
- **英文版用同一套编号**，只把词换成 `PlayerX`（1846 中文是玩家12 ↔ 英文是 Player12）。

## 4. 工具

```bash
cd D:/兵棋/18xx
export PYTHONIOENCODING=utf-8

python _tools/anonymize_18xx.py --map        # 看映射表（改分层口径后先跑这个）
python _tools/anonymize_18xx.py --contexts   # 导出每处命中的上下文 → _work/_anonymize_contexts.txt
python _tools/anonymize_18xx.py --apply --dry  # 只出变更清单，不写文件
python _tools/anonymize_18xx.py --apply      # 应用（自动先落快照到 _work/_anonymize_backup/）
python _tools/anonymize_18xx.py --check      # 校验无残留真名
```

产物：`_work/_anonymize_map.json`（映射表，**内部用，不发布**）、`_work/_anonymize_changelog.txt`（变更清单）。

> **⚠ 映射表是缓存的，不要每次重算**（2026-09-24 踩过）：映射表由「正文里出现的名字」反推，
> **文件一旦匿名化，正文里就没有真名了 —— 重算会得到空映射，`--check` 随之变成空转**（什么都查不出来）。
> 工具现在的行为：默认**读** `_work/_anonymize_map.json`；只有在「映射表里没有该作品 / 是空的 /
> 现行文件里还剩真名」时才重建。重建时优先读 `_work/_anonymize_backup/` 的快照（那里有真名），
> 新作品则读现行文件。必要时 `--rebuild` 强制重建。

**PPT 不在工具范围内**：它由 `_tools/build_18xx_ppt.py` 硬编码生成，
要**改脚本里的名字再重跑脚本**（`python _tools/build_1846_ppt.py`），不要直接改 pptx 的 XML。

## 5. 五道校验（**少一道都会出事**）

1. **误报核验**——`--contexts` 导出的上下文**必须逐条看**。踩过的坑：
   - `tool` 是英文版里的普通词（"a tool for strong players"），**不是玩家**；
   - `Tiles` 是 1880 日志格式串（"Available Tiles: Yellow"），**不是玩家**；
   - 真名 **`8`**（裸数字）会命中全文所有「8」，**无法安全匹配，永久排除**。
   这类名一律进 `anonymize_18xx.py` 的 `UNSAFE` 集合，并在旁边写清理由。
2. **教学段落改写**——「日志句式陷阱」章节里的名字往往是**日志语法示例**，直接替换会毁掉说明。踩过的 4 处：
   - 「玩家名含标点（`A`、`B`、`C`）」→ 改成「**原名含 `.`、`()` 等符号**，现记作 `玩家20`、…」
   - 「股息收款名单不能用 `[^,)]` 切分：`¥100 to X` 含括号」→ 改成「有玩家名**原名带 `()` 后缀**（现记作 `玩家23`）」
   - 「玩家名全大写（`X`）」→ 改成「**原名全大写**，现记作 `玩家12`」
   - 跨报告引用（1830 里「与 1846 的 `Subst` 同源」）→ 也要换成 1846 的编号 `玩家56`
   **尾随空格类的示例（`` `玩家7 ` ``）替换后天然成立，不用改。**
3. **行尾保留**——本目录 .md **行尾不统一**（多数 CRLF，英文版/术语表/358局稿是 LF）。
   工具已按各文件原始行尾还原，**改完必须复核**，否则整份文件会被 diff 成"全部改写"。
4. **`--check` 无残留**。
5. **正文可读性抽查**——随机读几段，确认没有"玩家X 的 <某个必须靠真名才成立的描述>"。
6. **⚠ 反向泄漏自查**（**2026-09-24 实际踩到**）——凡是**为了解释口径而点名**的地方，等于把已匿名的人重新指认出来。
   实例：1846 §1.5 写完 TOP 口径说明时写了「阈值口径会多出 cougar、Kubigaruma、mjmill13 三人」——
   这三人正是玩家1/玩家2/玩家3，一句话就把他们点名了。
   **正确写法**：用位置指代，不给名字——「会多出 **3 人**（RR ≥ 1900 却未进前 9 名者，见 §1.3 表的第 10–12 行）」。
   **凡是新增的解释性文字、版本沿革、勘误说明，写完都要再跑一遍 `--check`。**

## 6. 已知的、需要向读者交代的后果

- **跨作品不一致**：cougar 在 1880 是 TOP（真名）、在 1846 是玩家1；Amori 在 1846 是 TOP（真名）、
  在 1830 是玩家16。这是"各作品独立分层"的必然结果。**用户已确认接受**，但报告再版时若被问起要能解释。
- **旧版报告用新版映射**：`1846深度分析（312局/167局/72局）.md` 里的 TOP 名单是**那一版自己的分层**
  （例如 167 局版把 EASE99、JWG3、Welcome to die 列为 TOP），套用 672 局的映射后会出现
  「玩家6 … TOP」这种字样。**这是正确的**（标签属于那一版，编号属于现行作品口径），不要"修正"。
- **README.md 是跨作品索引**，按各作品自身的映射处理；同名在不同作品编号不同时**以先者为准**并出警告。

## 7. 版本与快照

匿名化是一次**交付物改动**，按 [[version-bump-convention]] 走：
- 主报告标题的 `· vX.Y` **升一位**，文首**版本沿革**里写明「玩家匿名化：TOP 组保留真名，MID/BOT 组记作玩家X」；
- 改前快照 `_work/_anonymize_backup/`（工具自动落），改后按老规矩落 `_work/<作品>_report/报告_vX.Y_YYYYMMDD.md`；
- **PPT 重生成后要目视自检**（见 `references/PPT交付.md`）。
