## 模板 A：新作品从零开始（最常用）

```
我要做《<作品名>》的数据分析，请走 skill `18xx-analysis` 的完整流程。
★ 开工先核验：skill 已迁至 D:\AI（本项目为 `D:\AI\.claude\skills\18xx-analysis\SKILL.md`）；若引用失效或指向旧路径，先纠正为 D:\AI 对应目录再开工；新建/修改 skill 一律落位 D:\AI 对应目录（C 盘为链接，勿删重建）。

【我的身份】<没玩过 / 玩过 N 次>，规则<已读 / 未读>，<X 月 X 日>要上桌。

【数据位置】D:\兵棋\18xx\复盘分析\<作品名>\
源文件 <N> 个，形态可能混杂（单局文件 / 带局头合订本 / 无局头合订本），
编号可能有重号错号，也可能混入别的作品，请自己识别、编号、查重。

【第 0 步 · 立规则】先逐条读该作英文原规（D:\兵棋\18xx\ 下），
确保没有规则错误，不要与 1830/1846/1862 混淆。把本作与它们的机制差异列成表。
中文译本只作对照，冲突以英文为准，发现误译请指出。

【硬性约束】
1. 对账不到基准不得下结论：逐玩家重算终局净资产，与日志官方结算比对，残差要分类解释。
2. 先分层再下结论：前二制 rank rating（1名+2、2名+1、3名起扣分），
   用 BT/RR 分分层，不能拿名次分组解释名次。
3. 所有结论四件套：频次 + 频率 + 胜率 + 案例编号；没有数据就说没有，不要编造。
4. 统计"组合"而非"频次"（例如首车要看车型组合，不是各类车买了多少次）。
5. 变体局（2人局等）单独标记，排除主统计。
6. 有随机属性的，不许跨局套用（例如某公司这一局拿到的许可证）。
7. 样本量必须标注；n<20 只作参考；小样本玩家不能和厚样本玩家等同看待。
8. 署名放文首：分析人 Pig9013，使用模型 Deepseek-flash。

【我要的答案】
1. 我是<水平>玩家，想知道这个游戏有哪些技巧、策略、套路、危机点、开局方法。
2. 对局分熟人局 / 路人局，观察差别。
3. 结合数据回答下列问题（每个都要频次/频率/胜率 + 案例）：
   ① <问题一，如：不同 SR 该开什么公司、定多少 par>
   ② <问题二>
   ③ <问题三>
4. 着重关注：<本作的关键机制，如 1862 的拍卖/许可/合并/爆车/超发>。
5. 请包涵 1830/1846/1862 中适合本作的问题，并对应该作特征提出新的统计口径。

【交付】一份主报告 <作品>深度分析（N局）.md，体例照 skill 的报告模板。
先做机制与公司层面，我确认后再往下。
```
