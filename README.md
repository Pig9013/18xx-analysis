## 二、方法（摘要）

| 阶段 | 做什么 | 闸门 |
|:--|:--|:--|
| **S0 立规则** | 逐条读本作英文原规，列出与已分析作品的九项机制差异 | 规则错误 = 全错 |
| **S1 入库** | 单局/合订本/无局头三种源文件切分；**按内容 sha1 去重**；规范编号 + `_mapping.csv` | 去重后样本唯一 |
| **S2 解析** | 写作品专属记账状态机，逐玩家重建现金/持股/净资产 | **末尾与官方结算逐玩家对账** |
| **S3 提取** | 复用 parse 状态机、只旁听不改动，批量出 `_full.json` | 对账率写进报告头 |
| **S4 统计** | 14 类专题脚本（首车组合、爆车、金库、顺位、砸价、评级…） | 每个数字可指回脚本输出 |
| **S5 报告** | 固定骨架：数据与对账→玩家层→机制与行为→速查→方法与局限 | 交付前自查清单 |

**几条硬口径**：

- 前二制 rank rating：第 1 名 +2、第 2 名 +1、第 3 名起 −(rank−2)；只构造"前二 vs 非前二"比较对；
- 归一化名次 =(名次−1)/(人数−1)，**场均名次不跨人数比较**；
- 前二率只在 ≥4 人局统计；n<20 的格子只作参考；
- 随机属性不跨局套用（1862 的经营许可每局重绑，必须拆到"公司 × 许可"）；
- 相关 ≠ 因果，每条因果嫌疑单列。

完整流程与 18 条铁律见 [skill](<skills/18xx-analysis/SKILL.md>)。

## 三、玩家匿名化

这是**每一份交付物**的强制要求（2026-09-24 起）：

- **TOP 组保留真名**（公开对局中的高水平玩家，保留可追溯性）；
- **MID / BOT 组一律记作"玩家X"**（英文版 `PlayerX`），编号按实力分降序、MID 段在前 BOT 段在后；
- 分层边界各作品独立（1846 按印出名单、1880 按 BT≥2.0、1830 按 BT≥1700/≤1420、1862 按 BT≥1700）；
- 交付前跑 `anonymize_18xx.py --check`，PPT 用 `build_*_ppt.py` 重生成（不手改 XML）。

## 四、数据来源与致谢

**全部对局数据来自 [18xx.games](https://18xx.games/) 及在该网站上游玩的玩家们**——是他们无偿公开的游玩记录，造就了这些分析。没有这些公开日志，本项目一局数据都没有。

- 报告文首、文末均带致谢；
- 对局日志原文与原解析脚本**不在本仓库**（体积与数据边界原因）；报告中的每个数字都标了脚本与口径，需要复核可开 Issue 联系。
