# Анализ данных партий в 18xx · процесс и отчёты

> Превращаем сотни публичных логов [18xx.games](https://18xx.games/) в подробные отчёты, **готовые к публикации и прослеживаемые до цифры**.
> Каждая таблица — результат разбора партий по одной и сверки по каждому игроку; каждый вывод несёт **число случаев + частоту + винрейт + номер примера**; если данных нет — так и говорим.

## 2. Метод (кратко)

| Этап | Что делается | Критерий |
|:--|:--|:--|
| **S0 Правила** | Читаем английские оригинальные правила игры пункт за пунктом и перечисляем девять механических отличий от уже разобранных игр | Ошибка в правилах = всё неверно |
| **S1 Загрузка** | Разбиение трёх типов исходников (одна партия / сборник / без заголовка партии); **дедупликация по sha1 содержимого**; сквозная нумерация + `_mapping.csv` | Выборка уникальна после дедупликации |
| **S2 Разбор** | Пишем для игры собственную машину учёта и по каждому игроку восстанавливаем деньги / пакеты акций / чистые активы | **Сверка с официальным итоговым расчётом по каждому игроку** |
| **S3 Извлечение** | Переиспользуем машину разбора parse, только слушаем и ничего не меняем, получаем `_full.json` пачкой | Доля сверки выносится в шапку отчёта |
| **S4 Статистика** | 14 тематических скриптов (набор первых поездов, train rush, казна, порядок хода, обвал котировок, рейтинги…) | Каждое число отсылает к выводу скрипта |
| **S5 Отчёт** | Фиксированный каркас: данные и сверка → слой игроков → механики и поведение → памятка → метод и ограничения | Чек-лист перед сдачей |

**Несколько жёстких соглашений**:

- Рейтинг по системе «первые два»: 1-е место +2, 2-е +1, с 3-го −(rank−2); строятся только пары сравнения «первые два vs. не первые два»;
- Нормированное место =(место−1)/(число игроков−1), **среднее место не сравнивается между разным числом игроков**;
- Доля попаданий в первые два считается только для партий с ≥4 игроками; ячейки с n<20 — только для справки;
- Случайные атрибуты не переносятся между партиями (в 1862 лицензии на эксплуатацию привязываются заново каждую партию, поэтому их приходится разбирать как «компания × лицензия»);
- Корреляция ≠ причинность; каждая причинная гипотеза вынесена отдельно.

Полный процесс и 18 железных правил — в [skill](<skills/18xx-analysis/SKILL.md>).

## 3. Анонимизация игроков

Это обязательное требование для **каждого материала** (с 2026-09-24):

- **Группа TOP сохраняет настоящие имена** (сильные игроки в публичных партиях, чтобы сохранить прослеживаемость);
- **Группы MID / BOT всегда записываются как «PlayerX»** (`PlayerX` в английской версии), нумерация по убыванию силы, сначала блок MID, затем блок BOT;
- Границы слоёв независимы для каждой игры (1846 — по напечатанному списку, 1880 — по BT≥2.0, 1830 — по BT≥1700/≤1420, 1862 — по BT≥1700);
- Перед сдачей запускаем `anonymize_18xx.py --check`, презентацию пересобираем через `build_*_ppt.py` (XML руками не правим).

## 4. Источники данных и благодарности

**Все данные о партиях взяты с [18xx.games](https://18xx.games/) и у игроков, которые там играют** — именно их бесплатно опубликованные записи сделали эти анализы возможными. Без таких публичных логов в проекте не было бы ни одной партии.

- Благодарности стоят в начале и в конце каждого отчёта;
- Исходные логи партий и оригинальные скрипты разбора **в репозитории отсутствуют** (из-за объёма и границ по данным); каждое число в отчётах помечено скриптом и методикой, для проверки можно открыть Issue.
